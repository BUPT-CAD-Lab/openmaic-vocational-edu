OpenMAIC 支持两类互补能力：

- **RAG / 本地知识库**：让课堂生成过程基于用户上传或索引的参考资料。
- **职教 Widget**：生成面向实操训练的任务式、步骤式交互内容。

这两类能力可以独立理解和独立提交。RAG 侧重资料依据、检索结果和证据链；职教 widget 侧重操作练习、步骤决策和过程反馈。

## RAG / 本地知识库

RAG 模块用于让课堂内容贴合指定资料，例如设备手册、课程讲义、行业规范、操作流程或学校内部教材。

### 功能范围

- 提供服务端知识库，用于管理已索引文档。
- 将参考资料切分为文本块，并生成向量索引用于检索。
- 在课堂生成前提供 **Local Knowledge / 本地知识** 开关。
- 根据用户的课堂需求检索相关资料片段。
- 在生成继续前展示检索片段，允许用户确认使用哪些内容。
- 保存本次生成的证据快照，便于在生成后的课堂中查看来源和引用片段。

### 使用流程

1. 在知识库中上传或索引参考资料。
2. 在生成课堂前开启 **Local Knowledge / 本地知识**。
3. 输入主题、教学需求或上传材料并开始生成。
4. 在生成预览阶段查看检索到的资料片段。
5. 确认片段后继续生成课堂内容。
6. 在生成后的课堂中查看证据面板，确认内容依据。

### 检索内容如何参与生成

用户确认后的资料片段可以进入生成链路，帮助模型遵循资料中的术语、操作顺序、限制条件和完成标准。典型用途包括：

- 让课程大纲贴合本地教材或规范；
- 让场景内容避免与参考资料冲突；
- 让 widget 使用资料中的步骤、参数或注意事项；
- 让教师动作与同一份资料依据保持一致。

### 适用场景

当课堂内容必须基于明确资料时，建议使用 RAG，例如设备操作培训、安全规范学习、合规流程讲解、校本课程生成、企业内部培训材料复用等。

## 职教 Procedural-Skill Widget

职教 widget 模块提供面向实操训练的任务引擎生成路径。核心 widget 类型是 `procedural-skill`，用于表达一个可练习、可反馈、可评估的操作流程。

### 功能范围

- 增加职教任务引擎模式，用于生成实操训练类场景。
- 增加 `procedural-skill` widget 类型，用于步骤化操作训练。
- 支持过程类型、任务目标、工具材料、操作步骤、成功标准和错误后果等结构化字段。
- 生成可点击、可反馈的学习者控制项，例如选择、测量、工具使用、检查或状态切换。
- 提供进度、反馈、重置和成功标准追踪。
- 使用平台已有的 widget 消息协议驱动教师动作和状态更新。

### Widget 行为要求

一个 procedural-skill widget 应包含：

- 明确可见的任务区域；
- 工具或材料说明；
- 有序步骤；
- 不只是 “Done / 完成” 的学习者动作；
- 测量读数、状态指示、检查结果或阈值判断等轻量操作代理；
- 对错误或不安全选择的后果反馈；
- 只有满足真实条件后才完成的进度与成功标准；
- 可以恢复所有学习者状态的完整重置逻辑；
- 支持 `SET_WIDGET_STATE`、`HIGHLIGHT_ELEMENT`、`ANNOTATE_ELEMENT`、`REVEAL_ELEMENT` 等已有平台消息类型。

### 适用场景

职教 widget 适合需要学习者执行步骤、做判断、看反馈的训练内容，例如设备点检、仪器校准、安全检查、流程交接、维修排障、实验操作、服务流程训练等。

## 两类能力的关系

RAG 和职教 widget 解决的是不同问题，因此可以保持解耦：

- RAG 提供资料依据和检索上下文。
- 职教 widget 提供实操交互和步骤训练。
- 课堂可以只使用职教 widget，不依赖 RAG。
- 课堂也可以只使用 RAG，不使用职教 widget。
- 当两者同时启用时，RAG 检索结果可以帮助职教 widget 更贴近资料中的真实流程。

这种拆分可以让知识库能力、任务引擎能力和文档说明分别提交，降低 PR 冲突和评审成本。
